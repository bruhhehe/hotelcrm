# Decisions

What was chosen, why, and when. Newest phase at the bottom. If you're about to change one of
these, update this file in the same commit.

## Phase 1 — Scaffold

| #    | Decision                                                                                                                                                                             | Why                                                                                                                                                                                                                                                                                                        |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.1  | **Next.js 15.5 + React 19**, App Router, `typedRoutes: true`                                                                                                                         | Spec. Typed routes catch broken internal links at build time.                                                                                                                                                                                                                                              |
| 1.2  | **TypeScript strict + `noUncheckedIndexedAccess`**                                                                                                                                   | Array/record lookups in the pricing engine (nightly prices, rate lookups) must handle "missing" explicitly. ESLint bans `any`.                                                                                                                                                                             |
| 1.3  | **Zod 4**                                                                                                                                                                            | Current major. `lib/env/schema.ts` is pure and unit-tested; `lib/env/server.ts` (server-only) and `lib/env/client.ts` wrap it.                                                                                                                                                                             |
| 1.4  | **All integration keys are optional**, validated for shape when present; paired keys (Google id+secret, Resend key+from, Twilio trio, Calendar id+secret) must be set together       | Spec §8: "not configured" is a UI state, not a crash. A malformed key still fails boot with every bad key listed. Empty strings count as unset (Vercel commonly leaves `""`).                                                                                                                              |
| 1.5  | Google Places key is **`NEXT_PUBLIC_GOOGLE_PLACES_KEY`**, not `GOOGLE_PLACES_KEY`                                                                                                    | It's used client-side (spec §2), and Next.js only exposes `NEXT_PUBLIC_*` to the browser. Restrict it by HTTP referrer in Google Cloud.                                                                                                                                                                    |
| 1.6  | **node-postgres (`pg`) driver** via `drizzle-orm/node-postgres`, not `@neondatabase/serverless` over HTTP                                                                            | The availability engine needs interactive transactions with `SELECT … FOR UPDATE` (spec §6.1); the Neon HTTP driver can't do that. `pg` works the same against Neon (use the pooled `-pooler` URL) and against local/CI Postgres, so tests run on a real database. Pool is cached on `globalThis` (max 5). |
| 1.7  | DB access via **`getDb()`**, which throws `DatabaseNotConfiguredError` when `DATABASE_URL` is unset                                                                                  | Nothing touches the DB at import time, so `next build` and the marketing site work before Neon is connected.                                                                                                                                                                                               |
| 1.8  | **Auth.js v5 (`next-auth@5.0.0-beta.32`)** with the Drizzle adapter, **database sessions**                                                                                           | Sessions can be revoked (remove a staff member → they're signed out), and memberships/roles are looked up server-side anyway. Falls back to JWT only when there's no DB, in which case there are no providers and nobody can sign in.                                                                      |
| 1.9  | Auth config is **lazy** (`NextAuth(() => config)`)                                                                                                                                   | Providers are registered only when configured. Magic link needs DB + (Resend, or non-production). Google needs DB + id/secret.                                                                                                                                                                             |
| 1.10 | **Dev magic links print to the console** when Resend isn't configured; production never does this                                                                                    | Spec §7 ("magic link printed to console in dev"). The guard is `NODE_ENV !== "production"`.                                                                                                                                                                                                                |
| 1.11 | Magic-link sign-in calls `signIn(…, { redirect: false })` then `redirect("/login/check-email")`                                                                                      | Otherwise Next.js follows Auth.js's `/api/auth/verify-request` hop as a soft navigation and the address bar shows the API URL.                                                                                                                                                                             |
| 1.12 | **Middleware only checks that a session cookie exists** (no DB, edge-safe); `(app)/layout.tsx` does the real check via `requireUser()`                                               | This is the Next.js pattern that keeps the DB out of middleware. A forged or expired cookie still gets redirected by the layout.                                                                                                                                                                           |
| 1.13 | Post-sign-in `callbackUrl` must be a same-origin path (`safeCallbackUrl`)                                                                                                            | Blocks open redirects: `//evil.com`, `/\evil.com`, absolute URLs.                                                                                                                                                                                                                                          |
| 1.14 | Staff auth tables are `users/accounts/sessions/verification_tokens`. **Guest-portal auth is a separate table + cookie** (Phase 9)                                                    | Spec §2. A guest must never be able to obtain a staff session.                                                                                                                                                                                                                                             |
| 1.15 | IDs are **cuid2** generated in the app (`lib/db/schema/_shared.ts`)                                                                                                                  | Spec §3. The id is known before insert, which is handy for idempotent writes and audit rows.                                                                                                                                                                                                               |
| 1.16 | **Migrations run before the build on Vercel** (`vercel-build` = `db:migrate && next build`), and are skipped when `DATABASE_URL` is unset                                            | With the Neon ↔ Vercel integration, each preview deploy gets its own DB branch, so previews migrate their branch and production migrates at promote time. `db:migrate` uses Drizzle's programmatic migrator, which is idempotent.                                                                          |
| 1.17 | Vercel region **`lhr1` (London)**                                                                                                                                                    | Demo tenant and primary market are UK. Pair it with a Neon project in `aws-eu-west-2`.                                                                                                                                                                                                                     |
| 1.18 | **Security headers**: `nosniff`, `Referrer-Policy`, `Permissions-Policy` everywhere; `X-Frame-Options: DENY` everywhere **except** `/stay/[slug]`                                    | The booking widget must embed in an iframe on hotels' own sites; nothing else should be frameable, including the guest portal (`/stay/[slug]/account`).                                                                                                                                                    |
| 1.19 | **UI primitives written by hand in shadcn style** (`components/ui/*`, Radix + CVA), not via the shadcn CLI                                                                           | The CLI is interactive, and the spec says to re-theme anyway. Tokens live in `app/globals.css` (`:root` vars → Tailwind v4 `@theme inline`).                                                                                                                                                               |
| 1.20 | Fonts: **Fraunces** (display, `font-display`) + **Inter** (body) via `next/font`                                                                                                     | Spec §9. Self-hosted at build time, so there's no runtime request to Google.                                                                                                                                                                                                                               |
| 1.21 | Sections not built yet show an **honest "Not set up yet" empty state**, and quick-create items are disabled ("Soon")                                                                 | "Never fake a feature." Each is replaced in its phase.                                                                                                                                                                                                                                                     |
| 1.22 | Dates are formatted in the **hotel's timezone** (`greetingFor`, `longDate`), with `Europe/London` as the default until hotels exist                                                  | The server runs in UTC. A London hotel at 00:30 BST must still see "today" as today.                                                                                                                                                                                                                       |
| 1.23 | CI = typecheck, lint, Prettier check, Vitest, `drizzle-kit check`, **schema-drift check** (generate must be a no-op), migrations applied to a real Postgres 16 service, `next build` | Catches "changed the schema but forgot the migration" before merge.                                                                                                                                                                                                                                        |
| 1.24 | Vitest config is `vitest.config.mts` with native `resolve.tsconfigPaths`                                                                                                             | Vite 7+ supports tsconfig paths natively, so `vite-tsconfig-paths` isn't needed.                                                                                                                                                                                                                           |
| 1.25 | Server code reads the session through **`getSession()`**, which returns `null` without calling Auth.js unless both DB and `AUTH_SECRET` are set                                      | Keeps an unconfigured deploy quiet instead of logging `MissingSecret` on every request. Sign-in needs `AUTH_SECRET` in dev too, because Auth.js requires it everywhere.                                                                                                                                    |
